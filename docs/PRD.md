# 模糊音克星 (fuzzy-pinyin-fixer) — 产品需求文档 (PRD)

> 状态: v1.0 | 日期: 2026-08-15 | 基于需求对齐 (grilling) 结论

## Problem Statement

方言地区用户在学习普通话时，普遍存在**模糊音混淆**问题：前后鼻音不分（in/ing、en/eng）、声母不分（l/n）等。这些问题在输入法中被固化为"模糊音"设置，掩盖了发音错误。用户需要一款工具，通过**反复练习**暴露并纠正这些音位混淆，最终"认全常用字"。

现有工具的问题：

- 通用测题工具不针对特定音对，干扰项与目标音无关，训练效果差；
- 词库脱离字频数据，练习到生僻词，偏离"常用字优先"的目标；
- 没有错题闭环，用户反复在同一个字上犯错而不知。

## Solution

一款**纯前端、零依赖、本地运行**的纠音练习工具：

- 基于**25 亿字语料字频表**筛选出前 3000 常用字，提取其中涉及模糊音的目标字（约 600+ 字）构成题库；
- 题目以"**整词展示 + 目标字高亮 + 二选一**"形式呈现：如"**天津**"考"津"，选项为 `jīn / jīng`；
- 支持**专项练习**（按音对选择，如只练 in/ing）与**综合随机**双模式；
- 答对可标记"已掌握"，该字不再出现；答错自动进入错题本，支持一键重练；
- 数据存 localStorage：错题本、练习历史、设置、已掌握列表；
- 统计页展示总正确率、最近 7 天趋势、各音对正确率分布。

## User Stories

1. 作为**方言用户**，我想要专项练习 in/ing 音对，以便集中攻克我最严重的混淆点。
2. 作为**用户**，我想要看到整词（如"天津"）并定位到目标字（"津"），以便在真实语境中记忆读音，而不是孤立记字。
3. 作为**用户**，我想要二选一作答并立即看到正确答案（含声母/韵母分色展示），以便快速理解差异。
4. 作为**用户**，我想要把答对的字标记为"已掌握"，以便它不再出现，专注剩余生字。
5. 作为**用户**，我想要查看并管理"已掌握"列表，以便随时撤回误标记。
6. 作为**用户**，我想要答错的字自动进错题本，以便集中重练。
7. 作为**用户**，我想要每轮结束后看到正确率与错题清单，以便了解进步情况。
8. 作为**用户**，我想要查看历史统计（总正确率、30天趋势、音对分布），以便追踪长期进步。
9. 作为**用户**，我想要自定义每轮题量（5/10/20/自定义 1-1000），以便控制练习时长。
10. 作为**用户**，我想要无限模式（不设题数上限，题库练完自动循环），以便自由练习。
11. 作为**用户**，我想要在手机浏览器上正常使用，以便随时练习。
12. 作为**用户**，我想要在多个设备（公司电脑/家里电脑/手机）间自动同步学习进度，以便换设备继续练习，无需手动导出导入。
13. 作为**用户**，我想要应用自动完成云同步（无需每次手动点"同步"按钮），以便无感地保持各端数据一致。
14. 作为**用户**，我想要为我的数据指定一把"同步密钥"（应用自动生成），以便只有我能访问我的云端数据；新设备输入同一密钥即可接管进度。

## Implementation Decisions

### 架构

- **纯前端原生 HTML/CSS/JS**，零构建、零依赖、零后端；双击即可运行；全部使用相对路径，可直接部署到任意静态托管（GitHub Pages / CloudStudio）。
- 单页应用，视图切换（主页/练习/统计/已掌握管理）通过 JS 控制，无路由库。

### 题库数据模型

- 候选字数据源：`Chinese character list from 2.5 billion words corpus ordered by frequency.xlsx`（25 亿字语料，14977 字），取前 3000 常用字。
- 目标字提取规则：按音对筛选——
  - in/ing：读音以 `in` 或 `ing` 结尾
  - en/eng：读音以 `en` 或 `eng` 结尾
  - l/n：声母为 `l` 或 `n`
- 实测候选量：in/ing 211 字、en/eng 201 字、l/n 289 字（字有重叠，去重后约 664 字），**全部纳入题库**；其中 66 个为 2026-08-16 依据词频表补充（`docs/missing_keywords_analysis.json` 检出）。
- **多音字处理**：读音归属校验——目标字在该词中的实际读音必须属于该音对；多音字按读音分属各组（如"行"的 xíng 入 ing 组、"亲"的 qīn 入 in 组、qìng 入 ing 组）。组词阶段强制校验，避免无效题。
- **组词策略（v2，2026-08-16）**：依据《现代汉语语料库词频表.xls》（cncorpus 2000 万字语料）为每个候选字组 **2-5 个词**：
  1. 词频表匹配词数在 2-5 → 全部纳入；
  2. 匹配词数 >5 → 取词频最高的前 5 个；
  3. 匹配词数 <2 → 追加人工词库（`scripts/words_data/backup/`，原 v1 人工精选词）去重兜底。
  pypinyin 仅用于校验所选词中目标字读音归属，不承担选词。
- 词条规模：共 726 条目 / 2588 词条（in/ing 896、en/eng 767、l/n 1169）；多音字按词中实际读音拆分条目。
- 数据格式：JSON 文件（`data/` 下），结构为按音对分组的目标字词库；导出为可审计、可调整的结构化数据。

### 题目生成

- 每轮题量默认 10 题，可配 5/10/20；「自定义」支持输入 1-1000 题；「无限」模式不设上限，题库练完自动重新洗牌补题（优先不重复本轮已出过的字），由用户主动结束。
- 同一轮内不重复目标字。
- 出题池 = 候选字 − 已掌握字。
- 题型：
  - 词语题：整词展示，目标字下加圆点/下划线 + 轻微放大高亮；
  - 单字题：目标字即全字，高亮整个字；
  - **多字题**：词内多个可考字（属音对库、且词中实际读音匹配）时，每字一行、各给两个读音选项，**全部行作答完才提交**（如「新娘」→ 新 xin/xing + 娘 niang/liang）；每行对错独立记入流水，整题全对才算答对。
- 选项：二选一，带声调拼音（如 `jīn / jīng`）。
- **双音对字 4 选项**：目标字读音同时命中鼻音韵母组（in/ing 或 en/eng）与 l/n 声母时（如「凝」níng、「林」lín），给出 4 个选项 = 正确 + 韵母混淆（in↔ing / en↔eng）+ 声母混淆（l↔n）+ 双重混淆，覆盖两个音对的考法；差异高亮统一按韵母维度（n/ng 加粗）。

### 交互流程

- 作答 → 立即揭示对错：
  - 正确拼音展示时，**声母/韵母分色**（高亮差异点，如 in vs ing）；
  - 约 1 秒后自动进入下一题。
- **已掌握（右上角常驻按钮）**：随时标记/撤回，**与对错判定完全解耦**——
  - 点击标记 → 揭示正确选项；标记后该字不再出题；错题本对应记录置为失效（隐藏但保留，撤回时恢复）；
  - 未作答时点已掌握 = 跳过本题（不计对错）；多字题弹出多选（可标记部分字）；
  - 标记后统一 1 秒自动进入下一题；再次点击可撤回（选项显示复原）。
- **上一题回溯（左下角按钮 / 快捷键 ←）**：本轮内回看任意已答题——
  - 回到的题目显示"已作答状态"（选项锁定 + 对错标色 + 反馈），**不能改答案**，但可标记/撤回已掌握；
  - 回溯不影响轮次统计；底部「继续作答」按钮回到最新题；无限模式同样支持；
  - 回溯时暂停自动下一题计时。
- 答错 → 自动记入错题本（已掌握而失效的记录不展示、不参与错题重练）。
- 轮末复盘页：正确率 + 错题清单 + "错题重练"入口。
- **FSRS 记忆调度**（默认开启，设置页可关）：
  - 每答一题，调度器立即更新该字卡片记忆状态（stability/difficulty/到期时间），**第一题即生效，无需数据积累**；
  - 出题策略：**到期复习队列优先**（`due <= now` 的字交错随机先出，来源标记 `fromFSRS=true`），不足再随机补充新字；
  - 生疏的字复习更频繁、熟练的字间隔拉长；设置页显示"待复习 X 字"；
  - 关闭开关 → 回滚到纯随机出题（旧逻辑保留，`buildQuestionsRandom`）；随时可重新开启；
  - 算法：FSRS-6（21 参数，移植自 fsrs4anki v6.1.1），纯前端零依赖（详见 `docs/fsrs-scenario.md`）。
- **设置页 · 数据备份与迁移**：
  - 数据概况：答题流水/字卡/错题本/已掌握 数量；
  - 「导出备份」：打包全部 6 张表为版本化 JSON 文件下载（`fpf-backup-YYYYMMDD-HHMM.json`）；
  - 「导入数据」：选择备份文件 → 校验（应用标识/版本/结构）→ 与本地**双向合并**（不覆盖）→ 展示新增统计；
  - 用途：换设备恢复进度、配合坚果云等同步盘实现多端同步（详见 `docs/sync-plan.md`）。

### 数据存储 (localStorage)

- `wrongBook`：错题记录（目标字、音对、错选读音、时间），去重累积；条目含 `hidden` 字段——该字标记已掌握时置为失效（隐藏不参与重练），撤回已掌握时恢复。
- `mastered`：已掌握目标字集合（按字标记）。
- `history`：每轮练习记录（日期、模式、音对、题数、正确率）。
- `settings`：默认题量、音对勾选状态等；`enableFSRS`（记忆调度开关，默认 true）。
- `reviews`：**每次作答流水（对错都记）**，追加式；字段含 char/pair/ts/rating/elapsedDays/word/读音/mode/source/fromFSRS 等，兼作 FSRS 记忆模型训练语料（详见 `docs/data-schema.md`）。
- `cards`：每字当前状态（练习次数、对错计数、FSRS 调度字段 state/stability/difficulty/due/scheduledDays——FSRS 开启时每次作答后更新）。
- **导入合并策略**（跨端同步的数据基础，详见 `docs/data-schema.md` 第五节）：
  - `reviews` 按 (char, pair, ts) 去重合并（append-only，绝不覆盖）；
  - `cards` 按 key 合并、同 key 取 `lastTs` 较新者（FSRS 记忆状态随卡整体迁移）；
  - `wrongBook`/`mastered` 按 key 合并、冲突取时间戳较新者（wrongBook 替换时保护本地 `hidden` 标记）；
  - `history` 整条去重；`settings` 本地有记录则本地优先、否则采用备份值。

### 多端同步（云同步，2026-08-16 新增需求）

**目标**：多设备间**全自动**同步学习进度（答题流水 / 字卡 / 错题本 / 已掌握 / 设置），用户零手动操作。技术方案见 `docs/sync-plan.md`（Cloudflare Workers + KV，免费无服务器）。

**用户故事（自动同步）**：打开应用 → 应用自动从云端拉取并合并数据 → 练习中每答一题自动增量推送 → 关闭页面时静默刷新 → 下次任何设备打开即是最新进度。全程无需点击"同步"按钮。

#### 同步密钥（身份模型）

- 应用首次开启同步时，用 `crypto.getRandomValues` 自动生成 **32 字节随机密钥**（`fpf-` 前缀 + base64url，约 43 字符），即"数据空间钥匙"；密钥**由应用生成，非平台颁发**。
- 密钥存在浏览器本地，自动携带，用户无感；设置页可查看 / 复制 / **重置密钥**（重置 = 生成新空间，旧空间数据保留但不再被认领，提示先导出备份）。
- 新设备接入：设置页输入同一密钥 → 首次拉取合并 → 此后自动同步。
- 任何人可生成自己的密钥开启自己的空间（密钥即身份，无账户系统）；隔离性依赖密钥熵（256-bit，禁止自定义弱密钥）。

#### 自动同步机制（核心需求）

| 触发时机 | 动作 |
|---|---|
| 应用启动 / 页面加载 | 静默拉取云端 → 双向合并 → 写本地（复用导入合并逻辑）|
| 每次作答（答题 / 标记已掌握 / 错题本变更）| 打"脏标记"，**防抖 3~5 秒**后批量推送增量 |
| 轮次结束（复盘页出现）| 立即推送 |
| 页面隐藏 / 关闭（visibilitychange / beforeunload）| 尽力推送未同步变更 |
| 推送失败（断网 / 服务不可用）| 保持脏标记，指数退避重试；下次启动/网络恢复自动补推 |

- **同步方向**：双向。拉取 = 云端并入本地（不丢本地）；推送 = 合并后的本地全量/增量写云端（幂等）。
- **冲突策略**：复用 `data-schema.md` 第五节合并规则——reviews 按 (char,pair,ts) 去重（append-only 永不丢）、cards/对象表取时间戳较新、settings 本地优先。单用户多设备几乎不会冲突。
- **离线可用**：同步是附加能力，非依赖——断网时本地照常练习，恢复后自动补齐。
- **状态可见**：设置页显示 同步状态（上次同步时间 / 待推送条数 / 错误提示）；顶栏可加小图标（可选）。

#### 数据范围与格式

- 同步内容 = `exportData()` 的 6 张表（reviews/cards/wrongBook/mastered/history/settings），版本化 JSON（v2）。
- 推送体积：单次全量 <10MB（本项目流水上限 3 万条），先全量推送（gzip 传输），未来数据量大再做增量（按 `ts > lastSyncAt` 拉取流水）。

#### 安全需求（详见 sync-plan 威胁模型）

- 密钥格式校验（Workers 端正则白名单），防 KV key 注入；
- HTTPS 传输，密钥放自定义 Header（不进 URL/日志）；
- Workers：请求体大小上限（2MB）、单空间容量上限（5MB）、按 IP+密钥限流（如 30 次/分钟）；
- 前端：所有用户可控数据渲染前转义（已有 escapeHtml）+ 导入/同步数据只当数据解析；
- 可选增强：端到端加密（AES-GCM，密钥派生，云端只见密文）；
- CSP 响应头（`default-src 'self'`）兜底。

#### 开关与回滚

- 设置页「自动云同步」开关：默认关闭（首次使用需主动开启并生成密钥）；关闭 = 完全回到纯本地模式，本地数据不受影响，随时可再开启（同密钥重新接管）。
- 同步功能独立于核心练习——即使 Workers 服务下线，应用本地功能完好。

### 统计页

- 总正确率；
- 最近 7 天每日正确率趋势；
- 各音对正确率分布。
- 后续可基于 `reviews` 流水扩展字级统计（每字练习次数、对错次数、薄弱字 TOP）与 FSRS 间隔重复调度。

### UI

- 中文界面；
- 浅色主题、简洁、大字号（选择题场景需大字易读）；
- 响应式布局，手机/桌面均可用；
- 答题对错用绿/红标识。

## Testing Decisions

- 测试范围：纯前端项目，重点测试**题库数据完整性**与**题目生成逻辑**：
  - 词库数据校验（脚本）：每个目标字属于且仅属于其音对；每个词中目标字读音确实属于该音对；无重复词条；词为常用词。
  - 题目生成逻辑（脚本/手动）：出题池排除已掌握字；同一轮内不重复；选项为正确读音与音对混淆音；单字/词语题渲染正确。
- 由于零依赖纯前端，采用 Node 脚本做数据层测试 + 浏览器手动验证交互层。

## Out of Scope

- **多端同步**：已纳入需求（见"多端同步（云同步）"章节，Cloudflare 方案）；账户系统（注册/登录/密码找回）暂不做——当前"密钥即身份"模型满足个人多端同步，若未来开放多用户再升级（`docs/sync-plan.md` 有演进预留）。
- 真人发音朗读 / TTS（列为未来扩展）。
- 除 in/ing、en/eng、l/n 外的音对（如 an/ang、f/h、平翘舌）——**架构预留扩展位**，数据结构支持新增音对分组。
- 4 选 1 / 多选等复杂题型。
- 游戏化（积分、排名、成就）。

## Further Notes

- 项目名：中文"模糊音克星"，英文 `fuzzy-pinyin-fixer`。
- 词库最终以 JSON 交付，作为独立数据资产，便于后续扩展与人工校对。
- 已掌握列表与错题本形成学习闭环：错题 → 重练 → 掌握 → 不再出现。
- 首版完成标准：本地双击可用、词库完整、核心练习闭环跑通、统计页可看。
