# TTS 答题朗读功能 — 需求文档 (PRD)

> 状态: 草案 v0.2（已吸收评审反馈：统一读 1 遍 + 手动朗读图标 + 切题计时协同） | 日期: 2026-08-20 | 关联: docs/PRD.md（主 PRD）、docs/design-spec.md

## Problem Statement

本项目帮助用户纠正模糊音（in/ing、en/eng、l/n），但全程只有**视觉反馈**（文字标色 + 拼音），用户无法建立"正确读音"的**听觉印象**。而模糊音纠正的本质是听辨与发音训练——听不到标准读音，纠音效果大打折扣。尤其在答错时，用户看到了正确拼音文本，却不知道它实际怎么读。

## Solution

作答后（无论答对答错）**自动用 TTS 朗读**题目内容，用听觉强化正确读音：

- 纯前端实现（Web Speech API），零成本、离线可用，符合项目"纯前端、零依赖、本地运行"的定位；
- 提供两处开关：**答题页右上角**快捷开关 + **设置页**总开关，状态实时同步；
- 不支持 TTS 的环境自动静默降级，不影响答题主流程。

## User Stories

1. 作为**用户**，我想要每次作答后自动听到词语的标准读音，以便用听觉巩固正确发音。
2. 作为**用户**，我想要在答错时也能听到正确读音的朗读，以便当场纠正错误发音印象。
3. 作为**用户**，我想要在答题页随时开/关朗读（如公共场所不便出声），以便不打断练习节奏。
4. 作为**用户**，我想要在设置页管理朗读开关，以便设定长期偏好并随云同步到其他设备。
5. 作为**用户**，我想要作答后手动反复点击词语旁的朗读图标重听，以便按自己的节奏强化记忆。

## 功能需求

### F1 朗读时机与内容

| 场景 | 朗读内容 | 说明 |
| --- | --- | --- |
| 单字题作答后 | 目标字本身（如"津"） | 答对答错都读 |
| 词语题作答后 | 完整词语（如"天津"） | 词语语境朗读，TTS 按文本自然发正确音 |
| 多字题整题完成后 | 完整词语朗读 1 次 | 逐行作答期间不朗读，避免打断节奏 |
| 回溯查看已答题 | **不朗读** | 仅作答动作触发 |

朗读策略细节：

- **答对答错统一自动朗读 1 遍**；需要重复强化时由用户手动点击词语旁的朗读图标（见 F5）；
- 永远只朗读**正确读音对应的文本**（字/词），不朗读用户选错的拼音——拼音文本交给 TTS 会逐字母读（如 "j-ī-n"），听感差且无教学价值；
- 语速设为 **0.9**（略慢于默认），利于辨音学习；
- 切题、结束轮次、离开答题页时立即 `cancel()` 停止残留语音。

### F2 开关 — 答题页右上角

- 位置：`quiz-toolbar` 右侧、「已掌握」按钮**左边**，新增按钮 `#btnTtsToggle`；
- 两态展示：开启 🔊（默认态样式）/ 关闭 🔇（灰化样式），与现有 `#btnMasteredTop` 的两态样式规范一致；
- 点击即切换并持久化，不打断当前题目；toast 提示「朗读已开启/关闭」。

### F3 开关 — 设置页

- 新增卡片「语音朗读」，与「记忆调度（FSRS）」卡片同级同款式（标题 + 描述 + switch 开关）；
- 描述文案：「作答后自动朗读字词的普通话读音，帮助建立听觉印象。使用设备自带的语音引擎，无需联网。」
- 不支持 TTS 的浏览器：该卡片显示灰色提示「当前浏览器不支持语音朗读」，开关禁用。

### F4 状态与持久化

- 设置字段：`settings.ttsEnabled`，**默认 `true`**（首次使用即有声，符合功能预期；不想出声可一键关闭）；
- 两处开关读写同一份 `Store.getSettings().ttsEnabled`，任一入口切换后另一入口下次渲染即同步；
- 随现有导出/导入与云同步机制流转（settings 中非设备级字段，与 `enableFSRS` 同等对待，无需改 `exportData`）。

### F5 手动朗读图标（反复强化）

- 位置：答题卡内词语/单字展示区（`.quiz-word`）右侧，图标按钮 🔉；
- 显示时机：**仅在作答后出现**（作答中隐藏，避免未答题就试听）；多字题在整题完成后出现；回溯查看已答题时同样显示且可点；
- 点击行为：朗读该题词语（单字题读单字）1 次，可反复点击；朗读中再次点击则打断重播；
- 手动点击属于用户显式操作，**不受自动朗读开关约束**；但 TTS 不支持的环境依旧不显示。

### F6 自动切题与朗读的时序协同

- 现状：答对后等待 1 秒自动进入下一题（多字题整题答对、无限模式同）；
- 变更：**朗读结束后才开始 1 秒倒计时**，避免朗读未播完就切题被截断；
- TTS 关闭 / 不支持时：行为与现状完全一致（直接启动倒计时）；
- 兜底保护：个别浏览器 `onend` 事件可能不触发，用「估算时长（字数 × 350ms + 500ms 缓冲）」作为超时上限，与真实结束事件竞速（Promise.race），保证流程不卡死。

## 选型方案

### 候选对比

| 方案 | 质量 | 成本 | 离线 | 隐私 | 部署改动 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| **A. Web Speech API**（`speechSynthesis`，设备自带 TTS 引擎） | 中等（取决于设备语音包：iOS「婷婷」、Android「Google 普通话」、Windows 晓晓等，均为标准普通话） | 免费 | ✅ 完全离线 | ✅ 不出设备 | 无，纯前端 | ✅ **采纳** |
| B. 云端 TTS（百度智能云 / Azure / 火山引擎） | 高 | 按量付费，需 API Key 与服务端代理（Key 不能暴露在前端） | ❌ | ⚠️ 请求出设备 | 需 Worker 代理，违背零依赖定位 | ❌ 暂不采纳 |
| C. Cloudflare Workers AI TTS | 较高 | Workers AI 计费 | ❌ | ⚠️ 请求出设备 | 需扩 cloudflare worker + 鉴权 | ❌ 暂不采纳，留作未来可选增强 |
| D. 预生成离线音频（离线 TTS 按词预渲染打包） | 高且稳定 | 免费 | ✅ | ✅ | 词库 600+ 字 × 词语，音频体积预计 10MB+，PWA 包体与构建复杂度大增；多音字需按词条逐一核对 | ❌ 不采纳 |

### 采纳结论：方案 A（Web Speech API）

理由：

1. 与项目"纯前端、零依赖、本地优先、离线可用"的架构定位完全一致，零成本零部署改动；
2. 主流设备中文语音包均为标准普通话，满足"建立正确听觉印象"的教学目标（不追求播音级音质）；
3. 封装在独立模块 `js/tts.js` 中，未来如需升级云端 TTS（方案 B/C），仅替换模块实现，调用方不变。

### 已知局限与对策（方案 A）

| 局限 | 对策 |
| --- | --- |
| 语音列表异步加载（`getVoices()` 首次可能为空） | 监听 `voiceschanged` 事件缓存中文 voice；为空时退化为不指定 voice 直接朗读 |
| 个别旧浏览器 / WebView 不支持 `speechSynthesis` | 能力探测：隐藏答题页按钮、设置页显示不支持提示，主流程不受影响 |
| iOS 要求首次朗读在用户手势链内 | 朗读由"点击作答"触发，天然满足 |
| Chrome 长文本朗读约 15s 中断的已知 bug | 朗读文本为 1~4 字词语，无影响 |
| 快速连续作答导致语音堆叠 | 每次 `speak` 前先 `cancel()` |

### Web Speech API 与设备语音包 FAQ

**Q1：是调用设备本地自带的语音包吗？**
是。`speechSynthesis` 只是一个调度接口：浏览器把文本交给**操作系统自带的 TTS 引擎**合成播放，浏览器本身不内置语音包，朗读过程不经过网络。

**Q2：语音包是设备自带的还是需要额外下载？**

| 平台 | 自带情况 | 额外下载 |
| --- | --- | --- |
| iOS / macOS | 默认自带中文语音（婷婷等） | 可在 设置 → 辅助功能 → 朗读内容 → 声音 下载音质更好的增强版语音 |
| Android（Google 系） | Google TTS 引擎自带「Google 普通话」 | 可在 设置 → 系统 → 语言和输入法 → 文字转语音输出 更换/下载语音数据 |
| Android（国产厂商） | 大多自带 TTS 引擎（华为/小米/OPPO 等，部分用讯飞） | 同上，系统设置入口 |
| Windows 10/11 | 默认自带中文语音（慧慧/康康离线版） | 设置 → 时间和语言 → 语音 可添加更多；Win11 支持下载自然语音 |

极端情况：个别低端机/定制 ROM 完全没有中文语音包 → 朗读无声或发音异常；已有对策覆盖（能力探测 + 静默降级，不影响答题主流程）。

**Q3：用户能自定义音色、语速吗？**
两个层面：

1. **系统层面**（用户自助）：Android 的「文字转语音输出」、iOS 的「朗读内容」、Windows 的「语音设置」均可更换系统 TTS 音色与默认语速，网页朗读随之变化；
2. **页面层面**（代码可控）：API 允许指定 voice（从系统已装列表选）、语速 rate（0.5~2）、音高 pitch、音量——因此应用内提供语速/音色选择完全可行（列入 M2），唯一边界是可选音色受限于系统已安装的语音，网页无法自行下载语音包。

## 技术设计

### 模块结构

新增 `js/tts.js`（在 `index.html` 中先于 `app.js` 引入），暴露 `window.TTS`：

```
TTS.supported()      // boolean：环境是否支持 speechSynthesis
TTS.speak(text, opts) // 返回 Promise，播完或被 cancel 时 resolve；
                      // opts.ignoreSwitch=true 时跳过开关检查（手动点图标重听用）
TTS.stop()           // cancel 残留语音
TTS.enabled()        // 读 Store.getSettings().ttsEnabled
TTS.setEnabled(bool) // 写设置（Store.setSettings）
```

voice 选择策略：`getVoices()` 中筛选 `lang` 以 `zh` 开头者，按名称优先级取其一：含「普通话」> 含「Tingting」/「Yaoyao」> 任意 `zh-CN` > 任意 `zh`。

### 接入点（js/app.js）

| 位置 | 改动 |
| --- | --- |
| `submitAnswer()` 单字/词语题分支末尾 | `TTS.speak(文本)`；答对自动切题场景改为在其完成回调里启动 `autoNextTimer`（F6） |
| `finishMultiRow()` 末尾 | 整题完成后朗读词语 1 次，倒计时同样等播完再启动 |
| `.quiz-word` 渲染（`renderQuiz` / `renderAnsweredState`） | 作答后追加手动朗读图标，点击调 `TTS.speak(文本, { ignoreSwitch: true })`（F5） |
| `show()` 视图切换 | `TTS.stop()`（离开答题页停止残留语音） |
| `quiz-toolbar`（index.html） | `#btnMasteredTop` 左侧新增 `#btnTtsToggle` 按钮 |
| 设置页（index.html 静态卡片） | 新增「语音朗读」卡片 + `#ttsToggle` switch |
| `renderSettings()` / `renderQuiz` 工具栏渲染 | 按当前开关同步 UI 两态 |

### 朗读文本来源

- 词语题：`q.word.word`（题目对象自带）；
- 单字题：`q.char`；
- 多字题：`q.word.word`（整题共用一个词语）。

## 验收标准

1. 开启状态下，答对/答错都自动朗读 1 次；作答完成前不朗读、不出现朗读图标；
2. 多字题逐行作答不朗读，全部行完成后朗读词语 1 次；
3. 答题页右上角开关与设置页开关状态一致，切换即时生效并持久化（刷新后保留）；
4. 快速连续答题无语音堆叠；切页/结束轮次后无残留语音；
5. 回溯查看已答题不自动朗读，但朗读图标可见且可手动点击；
6. 不支持 TTS 的环境：无报错，答题页不显示开关与朗读图标，设置页提示不支持；
7. 导出备份 → 清空 → 导入后，`ttsEnabled` 偏好保留；
8. 移动端（375px）开关按钮与朗读图标不破版（沿用现有 quiz-toolbar flex-wrap 行为）；
9. 答对自动切题：朗读播完才开始 1 秒倒计时，朗读不会被切题中途截断；TTS 关闭/不支持时切题节奏与现状一致；
10. 朗读图标可反复点击重听，朗读中再点则打断重播。

## 里程碑

- **M1（核心）**：`js/tts.js` 模块 + 设置字段 + 两处开关 + 作答朗读 + 手动朗读图标 + 切题计时协同 → 满足全部验收标准；
